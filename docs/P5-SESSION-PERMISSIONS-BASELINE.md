## Product-layer capability

P5 introduces an authenticated Marketing Session contract:

```text
Tenant
+ Actor
+ Roles
+ Marketing Capabilities
+ Workspace Grants
```

Platform-mode browser storage is scoped by `tenant + actor`. Product actions combine a Marketing Capability with a Workspace Grant. Read-only users can inspect permitted Workspace state; write and execution actions are disabled when the required capability or Grant is missing.

Revoked Workspace data is filtered out of Today, Marketing Assistant, Evolution metrics, Evolution Candidate review, Learning polling and new-task Experience matching. A Candidate from a revoked Workspace cannot continue to influence new tasks even when it had previously been accepted.

Platform mode disables raw browser-cache bundle export because stale local cache may contain data from a Workspace whose Grant was revoked. Enterprise/team export must be generated by the trusted upstream using current authorization.

## Authorization boundary

Browser Session data controls UI and local cache isolation. It is not authorization truth. Product Route Handlers forward authenticated Cookie / Authorization context to the trusted AWKN product upstream. The upstream remains responsible for final authorization.

Production fails closed when the Marketing Session endpoint is unavailable unless local fallback is explicitly enabled.

## Scope

This baseline verifies the marketing product-layer session model, tenant/actor cache isolation, capability checks, Workspace Grants, revocation visibility, local persistence scoping, upstream identity forwarding, automated acceptance tests, TypeScript and production build.

It does not implement generic identity infrastructure, Agent Runtime, AWKN Engine, Memory OS or MCP internals.
